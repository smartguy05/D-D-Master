# Product demo video

Two cuts: **Demo**, the ~32s teaser (music only), and **Tour**, the ~2 min narrated feature tour
(see [Tour](#tour-the-narrated-cut)).

`marketing/demo-video/` builds the ~30s "Hearthmaster" product demo: real footage captured from a
live campaign, composed and animated in Remotion, cut to a YouTube Audio Library track. It is
**not** part of the pnpm workspace: use `npm` inside it, never `pnpm`.

`BRIEF.md` is the source of truth: creative spec, shot list, and the file contract between the
three stages below.

## Layout

| Path | What |
|---|---|
| `BRIEF.md` | creative spec, shot ids, `shots.json` / `analysis.json` schemas |
| `capture/` | Playwright scripts that drive a live session and record shots ([README](../../marketing/demo-video/capture/README.md)) |
| `public/footage/<id>.mp4`, `shots.json` | captured clips (CFR 60fps) with highlight timestamps; committed to git |
| `public/audio/track.mp3`, `analysis.json` | chosen track + beat grid (bpm, `windowStartSec`, `hitSec`); committed |
| `public/sfx/*.wav` | chime, dice, impact, stamp, sword, whoosh, made by `scripts/make-sfx.sh` (`npm run sfx`) |
| `public/stills/*.png` | fallback stills `<Shot>` shows when a clip is missing |
| `audio/CREDITS.md` | track credit and license notes |
| `voice/script.json` | Tour voice lines: narrator, DM and player lines (OpenAI speech API) and NPC/AI clips copied from the capture campaign |
| `public/voice/*.mp3`, `manifest.json` | generated by `npm run voice` (`scripts/make-voice.mjs`): silence-trimmed, loudness-normalised (-16 LUFS), with durations; committed |
| `public/footage/<id>.dialog.json` | what was said during a v2 take (DM/player log lines, NPC clip urls) with take-relative times (`capture/dialog.mjs`) |
| `src/` | Remotion project: `Root.tsx` (compositions `Demo` 16:9, `DemoVertical` 9:16 and `Tour`), `Tour.tsx` (the narrated cut), `timing.ts`, `data.ts`, `Demo.tsx`, `theme.ts`, `scenes/` (RoomHook, FeatureBeat, PhoneBeat, Montage, Walkthrough, RoomPullback, EndCard), `components/` (Shot, Camera, Room, Props, Hud, CombatOverlay, Effects, Overlays, InkCaption, Phone, Transitions) |
| `scripts/make-sfx.sh`, `scripts/stills.mjs` | ffmpeg-synthesised SFX; per-bar stills + contact sheet |
| `out/` | renders (git-ignored) |

## Stages

1. **Capture.** Run a copy of the campaigns against an isolated server (PORT=8790, Vite on 5180) so
   the real saves and the dev servers are untouched. The text-mode DM (`POST /api/dm/text`, then
   `/api/dm/say {text, playerId}`) runs the session live; `/api/tools/:name` and the physical-roll
   endpoints force beats (e.g. a natural 20). Frames come from CDP screencast in headless Chrome on
   the hardware GPU and are mapped onto an exact 60fps grid. The text DM costs OpenAI calls.
2. **Music.** Chosen in YouTube Studio's Audio library, then analysed with librosa for bpm,
   downbeats and the loudest hit. The edit never time-stretches: the timeline is 15 bars at the
   track's own bpm (110.7 BPM gives 32.5s).
3. **Compose.** `src/timing.ts` turns bpm into `beat(n)` / `bar(n)` frames (`TOTAL_BARS` 15,
   `DEFAULT_BPM` 120 until `analysis.json` loads); every scene boundary is in `BEATS` (hook, voice,
   map, npc, combat, phone, montage, host, walkthrough, pullback, end), so a new track changes one number. `data.ts` loads both manifests in
   `calculateMetadata`; `<Shot>` starts each clip so a highlight (picked by regex from
   `SHOT_CONFIG` or a per-use `keyword`) lands on a chosen frame, and falls back to a still if the
   clip is missing.

## Commands (in `marketing/demo-video/`)

```bash
npm install
npm run preview          # Remotion studio
npm run sfx              # regenerate public/sfx/*.wav (ffmpeg)
npm run stills           # out/contact-sheet.png, one frame per bar
node scripts/stills.mjs --frames=0,40,911   # specific frames
npm run render:draft     # out/draft.mp4, half-res
npm run render           # out/demo.mp4, 1080p60 H.264 CRF 18, AAC 320k
npm run render:vertical  # out/demo-vertical.mp4, 9:16
npm run voice            # public/voice/ from voice/script.json (VOICE_CLIPS_DIR=<capture data>/<campaign>/assets for clips)
npm run render:tour-draft  # out/tour-draft.mp4, half-res
npm run render:tour      # out/tour.mp4, 1080p60
node scripts/stills.mjs --composition=Tour --beat=2   # one still per bar
npm run typecheck
```

## Tour (the narrated cut)

`src/Tour.tsx` runs 55 bars at 110.7 BPM (~119 s): the whole track from its first downbeat
(`TOUR_AUDIO_START_SEC` 0.265). Scene boundaries (`S`) and voice cues (`VOICE`) are in beats. The
nat-20 burst lands on beat 72, the track's big hit (39.3 s). The NPC clip plays in the quiet break
at ~80 s. The music ducks to about 25% under every voice cue. Lines with `sub` get an on-screen
"THE DM" / player tag.

v2 footage comes from `capture/take-v2-*.mjs` on the isolated server, after `setup-v2.mjs`. That
script saves Pip from the demo campaign to the roster and hand-draws lighthouse walls and doors
(the map predates wall detection):
- `take-v2-light.mjs sprites|doors|combat|loot|phone`: orbit-camera sprite close-ups
  (`cam.mjs`: right-drag pans, wheel zooms, left-drag orbits the TV's OrbitControls), a door
  opening onto hidden skeletons, the initiative intro, loot pick-up, and the phone sheet.
- `take-v2-crit.mjs`: one recorded take per advantage attack, kept only on a real natural 20.
- `take-v2-victory.mjs`, `take-v2-npc.mjs` (attitude Indifferent +1 → Friendly),
  `take-v2-ai.mjs ai|split` (Pip as an AI seat; Quill splits off and `focus_scene` cuts the TV),
  `take-v2-host.mjs` (Party tab: add an AI player, bring Pip from the roster).

DM lines in the Tour are the live text DM's own replies from those takes (`*.dialog.json`),
voiced with the app's DM voice (`cedar`). NPC and AI-player lines are the server's own
`speak_as_npc` clips.

## Gotchas

- Record one page at a time: a second page (e.g. the phone) open in the background gets no
  screencast frames.
- `/player/<id>` takes a **player** id, not a character id.
- Copy every campaign whose assets a take touches into the scratch dir (a roster hero's portrait
  lives in its home campaign's folder), or the sprite is redrawn on join.
- A `host` `end_combat {outcome: "victory"}` is forced even with a foe standing; let the last
  kill auto-detect the victory for clean footage.

- The live mic-level meter can't be shown in text mode; the voice beat uses typed speaker tags.
- Screencast only emits frames when the page changes, so static UIs (host, phone) report low
  source fps; that's expected, not choppiness.
- Never show "D&D" / "Dungeons & Dragons" in the video (WotC trademarks); "Compatible with 5e ·
  SRD 5.2" is fine.
- YouTube Audio Library terms clearly cover use on YouTube; check them before posting elsewhere.
